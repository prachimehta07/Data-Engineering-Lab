# Architecture Notes

A section-by-section walkthrough of `enterprise_data_engineering_lifecycle.drawio` — read this alongside the diagram.

## 1. External Data Sources (top-left)
Everywhere data can enter the platform from outside: the customer website, mobile app, admin portal, payment gateway, order service, inventory database, and third-party supplier API. These are the true "birthplaces" of data before anything is processed.

## 2. Users (top-right)
Systems and people that either feed data in or consume it downstream: clickstream trackers, IoT warehouse sensors, CRM, ERP, email notification services, shipping partners, and the marketing platform. Some of these are sources, some are consumers — in enterprise systems the same system often plays both roles.

## 3. Generation column
Where data is literally created as rows/events:
- **OLTP PostgreSQL** — the transactional database holding Orders, Customers, Products, Payments, Reviews, Returns, Inventory, Sessions
- **Click Events / JSON Logs / CSV Imports** — semi-structured data generated by user behavior and batch imports
- Reliability metrics shown alongside (99.9% uptime, HTTPS, transactions/sec, monitoring) represent the operational guarantees expected even at the point of creation.

## 4. Ingestion column
How data moves from Generation into the rest of the platform:
- **Apache Kafka** — the real-time backbone; topics like `orders`, `payments`, `clickstream` let every downstream system subscribe without talking to the source database directly
- **Apache Flink** — processes Kafka streams continuously (batch/streaming, watermarking, windowing, checkpointing) for near-real-time aggregates
- **Apache Spark** — handles heavier batch ETL, CDC (change data capture), and filtering/transformation jobs

## 5. Storage column
Data is stored in layers of increasing trust and structure — this is the **medallion architecture**:
- **Bronze** — raw, immutable, append-only copies of everything that arrived (JSON, CSV, logs)
- **Silver** — cleaned, schema-validated, deduplicated, anomaly-checked
- **Gold** — business-ready: fact/dimension tables, KPIs, ML-ready datasets
- Alongside these sit the actual storage/warehouse engines used to hold this data at scale: **Snowflake, BigQuery, Redshift, Delta Lake, Iceberg** — shown as cylinders because they represent persistent storage systems, not processing services.

## 6. Transformation column
Where Silver/Gold data gets reshaped into something directly usable: cleaning, standardization, normalization, joins, window functions, feature engineering (for ML), business logic (customer lifetime value, dynamic pricing, recommendations), masking, deduplication, validation, enrichment, and schema evolution handling.

## 7. Serving column
How the finished data actually reaches people and systems: Power BI/Tableau dashboards, REST/GraphQL APIs, a recommendation engine, real-time dashboards, and executive reporting.

## 8. Consumers column
The actual humans/systems at the end of the chain: managers, customers, analysts, data scientists, executives, mobile apps, business teams, and external APIs.

## 9. Left rail — Security / Observability / Privacy / Governance
These four boxes run the full height of the diagram deliberately — they are not a "stage," they are **undercurrents** that apply at every stage simultaneously:
- **Security** — authentication, authorization, TLS, RBAC, IAM, encryption, secrets management, audit logging
- **Observability** — logging, tracing, metrics, alerts, health checks, pipeline monitoring (Grafana/Prometheus)
- **Privacy** — GDPR compliance, PII masking, consent management, data retention, hashing, tokenization
- **Governance** — metadata, cataloging, lineage, ownership, schema registry, versioning

## 10. Technology Stack row (bottom)
Maps each lifecycle stage to the concrete tools used to implement it — a quick-reference legend showing *what you'd actually install* to build each column.

## 11. Data State Evolution row (bottom)
Shows how the *data itself* — not the tools — changes shape as it moves through the pipeline:
`Raw Events → Streaming Records → Persisted Files → Validated Dataset → Curated Dataset → Business Intelligence → Predictions`
This row is the single best summary of the whole diagram: everything above it exists to move data along this one line.

## 12. Legend
Explains the shape/color conventions used throughout: rectangles for services, cylinders for storage engines, solid arrows for data flow, dashed arrows for monitoring connections, and color coding for security/privacy-related boxes.
